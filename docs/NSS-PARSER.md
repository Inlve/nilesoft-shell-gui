# NSS 解析与双向编辑

当前实现是结构级解析器，不是完整的 Shell 运行时解释器。

## 数据流

NSS 源码 → 保留全部文本的词法标记 → 结构节点与属性源码范围 → WinUI 属性面板。

修改属性 → 检查当前源码快照 → 检查替换值的结构 → 仅替换目标值 → 重新解析 → 更新菜单树与源码草稿。

源码编辑后重新解析菜单树，旧属性面板失效。只有顶部“保存”才写入现有属性的修改；快速添加和主题生成仍沿用原有独立保存流程。

## 已支持

- 菜单、菜单项、分隔符、修改/删除规则、设置、主题与嵌套命名块。
- 赋值属性、变量、裸标志、跨行属性列表、同行多个菜单项。
- 字符串、注释、括号嵌套，以及 CR/LF/CRLF 行列定位。
- 保留所有标记、空白、注释和未知表达式的原文及 UTF-16 偏移。
- 静态 import 递归加载；循环路径去重；注释里的 import 不会加载。
- 根据源码读取属性：明确的字符串常量解码为文字字段，其余保留为 NSS 表达式字段。
- 单属性无损修改、无操作保持原文、拒绝其他快照的属性和额外属性注入。

单引号允许 `@` 插值，双引号用于转义文字，参见 [官方字符串文档](https://nilesoft.org/docs/expressions/string)。无法安全解码的转义形式保留为原始表达式。

## 明确限制

- 表达式目前是保留源码的值范围，不建立完整运算符优先级语法树，也不验证全部函数、类型和属性名称。
- 结构检查通过不等于 Shell 一定能执行；运行期诊断仍以 Shell 日志为准。
- 不求值 `sel`、`wnd`、环境相关函数，不执行命令；动态 import 只展示，不解析其运行结果。
- 非常规/未来语法可能只能通过源码编辑。尚未支持任意源码与专用控件的百分之百互转。
- 未实现节点拖放、新增/删除任意属性、全局撤销栈和主题专用面板从任意表达式反向求值。
- 嵌套超过 128 层报告错误，不继续递归该区域。

## 验证

`tests/ShellManager.Tests` 覆盖标记逐字符往返、局部替换、嵌套块、跨行属性、Windows 路径、裸标志、插值保留、错误输入和过期快照。检测到本机 Shell 安装时只读验证全部 `.nss` 文件，绝不写入安装配置。

下一阶段应基于官方语法增加表达式 AST 和属性语义表，再为布尔、枚举、数字、颜色等生成专用控件；不能通过执行用户配置来推断 UI。
